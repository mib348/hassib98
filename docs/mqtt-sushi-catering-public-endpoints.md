# MQTT Public Endpoints for mqtt.sushi.catering

## Current Endpoint Policy

Use `mqtt.sushi.catering` for every public MQTT-facing endpoint. Keep Laravel and local monitoring on localhost.

| Surface | Public URL / Host | Local target | Notes |
|---|---|---|---|
| Raw MQTT over TLS | `mqtt.sushi.catering:443` | `127.0.0.1:9443` -> Mosquitto `8883` | External Raspberry Pi and tool clients use this. |
| Dashboard login | `https://mqtt.sushi.catering:8885/login` | `127.0.0.1:1885` -> Node-RED `1880` | Login-protected by Node-RED middleware. |
| Dashboard UI | `https://mqtt.sushi.catering:8885/ui` | `127.0.0.1:1885` -> Node-RED `1880` | Main monitoring dashboard. |
| Laravel internal MQTT | `127.0.0.1:1883` | Mosquitto `1883` | Never expose this publicly. |

## Client Identity and Topics

Raspberry Pi clients should connect with MQTT `ClientId` set to their location
slug. Example: `Standort 1` uses `standort_1`.

The dashboard displays that received `ClientId` as the location identity. If a
device connects without a `ClientId`, Mosquitto generates an `auto-*` value and
the dashboard marks it as autogenerated.

Server-to-RPi order topics:

```text
{env}/location/{location_slug}/orders/new
{env}/location/{location_slug}/orders/cancelled
{env}/location/{location_slug}/orders/updated
```

Server-to-RPi device command topic:

```text
{env}/location/{location_slug}/pi/command
```

The Pi subscribes to its exact command topic. Laravel publishes the two
currently supported commands with QoS 1 and `retain=false`, so a restart or
internet test is never replayed after a reconnect:

```json
{
  "event": "command",
  "command": "test_internet_connection",
  "timestamp": "2026-08-23T13:40:21+03:00"
}
```

```json
{
  "event": "command",
  "command": "restart_device",
  "timestamp": "2026-08-23T13:42:05+03:00"
}
```

The production prefix is `live`; development uses `dev`, according to
`MQTT_TOPIC_ENV`. `test_internet_connection` is a manual speed test and its
results should appear in the next `pi/status` heartbeat. A fresh heartbeat is
the device response currently shown by Tech Admin.

The separate **Check PI Response** button preserves the lightweight legacy
health-check protocol. The Pi must also subscribe to its exact check topic:

```text
{env}/location/{location_slug}/pi/check
```

Laravel publishes this message with QoS 1 and `retain=false`:

```json
{
  "event": "pi.check",
  "location": "Test Location",
  "location_slug": "test_location",
  "requested_at": "2026-08-23T13:40:21+03:00"
}
```

On receipt, the Pi should immediately publish its normal retained `pi.status`
heartbeat. This check does not run an internet speed test; only the explicit
`test_internet_connection` command should do that.

Bidirectional reconnect order synchronization:

```text
{env}/location/{location_slug}/orders/sync
```

RPi-to-server topics:

```text
{env}/location/{location_slug}/orders/fulfilled
{env}/location/{location_slug}/pi/status
```

Pi status heartbeats:

- Topic: `{env}/location/{location_slug}/pi/status`
- Interval: every 10 seconds
- QoS: `1`
- Retain: `true`
- ClientId: the same location slug, for example `standort_1`
- Laravel subscribes to the current env with `{env}/location/+/pi/status`
- Node-RED monitors both `dev/location/+/pi/status` and `live/location/+/pi/status`
- Dashboard offline threshold: more than 20 seconds without a fresh online heartbeat

Heartbeat payload:

```json
{
  "event": "pi.status",
  "client_id": "standort_1",
  "location_slug": "standort_1",
  "status": "online",
  "timestamp": "2026-06-03T10:00:00+02:00",
  "uptime_seconds": 3600,
  "app_version": "1.0.0",
  "ip_address": "192.168.1.10",
  "wifi_connected": false,
  "eth_connected": true,
  "wifi_strength": null,
  "cpu_temp": 52.6,
  "temperature": 4.8,
  "download_mbps": 95.4,
  "upload_mbps": 18.7,
  "ram_usage": 24.2,
  "disk_usage": 17.9,
  "lock_status": "locked",
  "door_sensor_status": "closed",
  "message": null
}
```

`cpu_temp` is the CPU temperature in degrees Celsius, while `temperature` is
the temperature inside the vending machine. They are independent fields and
must not be substituted for one another. `download_mbps` and `upload_mbps` are
numeric internet-speed values in Mbps. `eth_connected` and `wifi_connected`
must be JSON booleans. For an Ethernet connection, publish
`eth_connected: true` and `wifi_connected: false`.

Laravel and Node-RED use the time when they receive each heartbeat. A device
remains online at exactly 20 seconds and is shown offline after more than 20
seconds without another heartbeat.

Last Will payload on the same topic:

```json
{
  "event": "pi.status",
  "client_id": "standort_1",
  "location_slug": "standort_1",
  "status": "offline",
  "timestamp": "2026-06-03T10:00:00+02:00",
  "message": "MQTT client disconnected unexpectedly"
}
```

## Order Recovery After Reconnect

The Pi subscribes to its exact `orders/sync` topic and publishes an
`orders.sync.request` event to that same topic after every successful MQTT
reconnect. Laravel subscribes with `{env}/location/+/orders/sync`, queries
Shopify GraphQL directly, and publishes `orders.sync.response` back to the same
location topic.

Both directions use QoS 1 and `retain=false`. The topic location slug,
`client_id`, and payload `location_slug` must match.

Request:

```json
{
  "event": "orders.sync.request",
  "request_id": "2db9d18d-d6c8-4acd-82dd-7f35704d22d9",
  "client_id": "test_location",
  "location_slug": "test_location",
  "requested_at": "2026-07-22T10:00:00+02:00",
  "reason": "mqtt_reconnect"
}
```

Response envelope:

```json
{
  "event": "orders.sync.response",
  "success": true,
  "request_id": "2db9d18d-d6c8-4acd-82dd-7f35704d22d9",
  "client_id": "test_location",
  "location_slug": "test_location",
  "generated_at": "2026-07-22T10:00:02+02:00",
  "from_date": "2026-07-22",
  "to_date": "2026-07-29",
  "complete": true,
  "order_count": 0,
  "orders": []
}
```

The device ignores its own request event and only applies a response matching
its outstanding `request_id`. It replaces the local snapshot only when
`success=true` and `complete=true`; otherwise it keeps its local data and retries.
No database migration or phpMyAdmin query is required for this feature.

## Required `.env` Values

Laravel should keep using the local broker:

```env
MQTT_HOST=127.0.0.1
MQTT_PORT=1883
MQTT_TLS_ENABLED=false
```

Docker should use the `mqtt.sushi.catering` certificate and localhost proxy targets:

```env
MQTT_TLS_CERT_DIR=/www/server/panel/vhost/cert/mqtt.sushi.catering
MQTT_TLS_LOCAL_PORT=9443
MQTT_DASHBOARD_LOCAL_PORT=1885
```

## aaPanel / Nginx Dashboard Proxy

Create an HTTPS site/listener for `mqtt.sushi.catering` on port `8885`, using the `mqtt.sushi.catering` certificate, and proxy it to Node-RED:

```nginx
server {
    listen 8885 ssl http2;
    server_name mqtt.sushi.catering;

    ssl_certificate /www/server/panel/vhost/cert/mqtt.sushi.catering/fullchain.pem;
    ssl_certificate_key /www/server/panel/vhost/cert/mqtt.sushi.catering/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:1885;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto https;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
    }
}
```

## Raw MQTT on 443

If `app.sushi.catering` and `mqtt.sushi.catering` share the same public IP, raw MQTT on `443` requires SNI routing at the TCP layer. The MQTT SNI branch should proxy to `127.0.0.1:9443`.

Use this shape only after confirming your Nginx build has stream support:

```bash
nginx -V 2>&1 | grep -E -- '--with-stream|--with-stream_ssl_preread_module'
```

Stream routing shape:

```nginx
stream {
    map $ssl_preread_server_name $tls_backend {
        mqtt.sushi.catering 127.0.0.1:9443;
        default 127.0.0.1:8443;
    }

    server {
        listen 443;
        proxy_pass $tls_backend;
        ssl_preread on;
    }
}
```

The `default 127.0.0.1:8443` target means the existing HTTPS web vhosts must be moved behind that local HTTPS port before stream routing takes over public `443`.

## Verification

Dashboard:

```bash
curl -Ik https://mqtt.sushi.catering:8885/login
curl -Ik https://mqtt.sushi.catering:8885/ui
```

MQTT TLS:

```bash
openssl s_client -connect mqtt.sushi.catering:443 -servername mqtt.sushi.catering </dev/null
mosquitto_pub -h mqtt.sushi.catering -p 443 -u "$MQTT_USER" -P "$MQTT_PASSWORD" -t test/public -m hello --tls-use-os-certs
```

Laravel internal:

```bash
docker exec mosquitto mosquitto_pub -h 127.0.0.1 -p 1883 -t test/internal -m hello
```
